## 这是什么

`SKILL.md` 是一个 Claude Skill 文件。将它放入 Claude 的 Skills 目录后，你只需用自然语言描述你的 AI 产品，Claude 就会按照模板自动生成一份包含以下内容的完整 PRD：

- 业务背景与大模型必要性论证
- 需求清单（P0/P1/P2 优先级）
- 业务流程图 + 系统时序图（Mermaid，自动生成，不溢出）
- 模型选型对比（3个候选模型 A/B/C，含成本精算）
- System Prompt 完整示例（模块化结构）
- 评测体系（Golden Case 规范 + 评测自动化流程）
- 效果保障与迭代机制（含灰度 A/B 实验方案）
- AI 专项风险清单（10类风险，含规避策略）

## 与普通 PRD 模板的区别

| 对比维度 | 普通 PRD 模板 | 本 Skill |
|---------|-------------|---------|
| 模型选型 | 无 | 三候选对比表，含 TTFT、成本精算、Failover 机制 |
| Prompt 工程 | 无 | System Prompt 完整示例（ROLE/BOUNDARY/WORKFLOW/OUTPUT/SAFETY 五模块）+ 版本管理表 |
| 流程图 | 占位符 | 自动生成 Mermaid（业务流程图 + 系统时序图3张拆分 + 状态图 + 迭代流程图） |
| 评测体系 | 无 | Golden Case 规范、多维评测指标、发布卡点红线、评测集生命周期维护 |
| 风险 | 通用风险 | AI 专项10类风险（幻觉、断供、数据合规、广告法、Token 失控等）+ 处置优先级 |
| 迭代机制 | 无 | 5阶段迭代闭环（捕获→实验→回归→灰度→结算），数据驱动 |

## 安装方法

### 在 Claude.ai 中使用

1. 打开 [claude.ai](https://claude.ai)
2. 进入 **Settings → Skills**（或 Projects → 自定义 Skill）
3. 点击「Add Skill」，将 `SKILL.md` 的完整内容粘贴进去
4. 保存后，在对话中直接说「帮我写一份 AI PRD」即可触发

### 在 Claude API / 本地部署中使用

将 `SKILL.md` 放入你的 Skills 目录（路径取决于你的部署配置），Claude 会在对话开始时自动加载。

## 使用方法

### 最小输入（让 Skill 引导你补全）

直接说：

```
帮我写一份 AI PRD，产品是智能客服机器人
```

Skill 会识别缺失字段，**一次性**提问补全所有必要信息，不会反复追问。

### 完整输入（直接生成，无需追问）

提供以下信息，Skill 会直接生成完整文档：

```
帮我写一份 AI PRD：

产品名称：智能合同审查助手
版本：V1.0.0
业务背景：法务团队人工审合同耗时 3~5 天/份，存在漏判风险，
         需要 AI 辅助识别风险条款并给出修改建议
目标用户：B 端企业法务团队（内部工具）
核心功能：
  - 合同上传与解析（P0）
  - 风险条款自动识别与标注（P0）
  - 修改建议生成（P1）
  - 合同版本对比（P2）
业务目标：审查效率提升 80%，漏判率降低 60%
模型目标：风险识别准确率 ≥ 90%，JSON 格式正确率 = 100%
部署约束：私有化部署，合同数据不出境
是否微调：不涉及，纯 Prompt 工程 + RAG
```

### 只生成某个章节

```
只帮我写第五章模型选型部分，产品是 XXX，约束条件如下：...
```

## 生成的 PRD 包含哪些内容

生成文档共 **十一章**，结构如下：

```
【V{版本号}】{产品名称} PRD
│
├── 一、背景
│   ├── 1.1 业务背景
│   ├── 1.2 为什么用大模型解决（含 ROI 对比表）
│   ├── 1.3 竞品分析
│   └── 1.4 产品目标（业务目标 + 模型目标）
│
├── 二、需求描述
│   ├── 2.1 需求清单（P0/P1/P2 优先级）
│   └── 2.2 需求分类（功能需求 + 业务验收指标）
│
├── 三、业务流程图（Mermaid flowchart TD，含异常分支）
│
├── 四、系统流程图（Mermaid sequenceDiagram，拆分为3张）
│   ├── 图4-1 输入链路
│   ├── 图4-2 生成链路（按功能模式分支）
│   └── 图4-3 输出链路
│
├── 五、模型选型
│   ├── 5.1 选型约束条件（红线 vs 弹性线）
│   ├── 5.2 三候选模型对比表（A/B/C）
│   └── 5.3 最终选型与商业决策依据（含 Failover + 成本精算）
│
├── 六、Prompt 工程设计
│   ├── 6.1 System Prompt 示例（五模块结构）
│   ├── 6.2 Prompt 策略表（9 个维度）
│   └── 6.3 Prompt 版本管理表
│
├── 七、训练数据集（如涉及微调）
│
├── 八、评测体系
│   ├── 8.1 数据源捕获（5 渠道）
│   ├── 8.1.1 Golden Case 写作规范（含 JSON 模板）
│   ├── 8.2 评测标准（多维度量化指标）
│   ├── 8.3 评测自动化触发策略
│   ├── 8.4 发布决策卡点（MVP / 灰度 / 全量红线）
│   └── 8.5 评测集生命周期维护
│
├── 九、效果保障与稳定性策略
│   ├── 9.1 输出质量控制（输入层 / 推理层 / 输出层）
│   ├── 9.2 产品能力边界与声明设计
│   ├── 9.3 迭代机制（5阶段闭环 + 状态图 + 迭代流程图）
│   └── 9.4 灰度与 A/B 实验方案
│
├── 十、AI 专项风险清单（10 类风险）
│
└── 十一、附录（术语表 + 相关文档链接）
```

## 常见问题

**Q：触发词有哪些？**

说「PRD」「需求文档」「帮我写PRD」「AI产品文档」「generate PRD」等都会触发。

**Q：哪些场景不适用？**

- 传统软件 PRD（无 AI/LLM 功能）→ 请使用普通 PRD 模板
- BRD（商业需求文档）→ 超出本 Skill 范围
- 运营计划 / GTM 上市策略 → 属于 BRD/GTM 文档，不在 PRD 范围内

**Q：生成的流程图会溢出吗？**

不会。Skill 内置了 sequenceDiagram 拆分规则，系统流程图强制拆分为3张子图，每张参与者 ≤ 5 个，避免横向溢出。

**Q：`<!-- 待确认 -->` 标注是什么意思？**

当你未提供某个字段（如具体的成本预算、竞品名称），Skill 会用行业合理默认值填写，并在旁边标注 `<!-- 待确认 -->`，提醒你人工复核，避免遗漏。

**Q：生成的 System Prompt 可以直接用吗？**

可以直接作为起点，但建议根据你的实际业务边界调整 `# BOUNDARY` 和 `# SAFETY` 两个模块，并按 Prompt 版本管理规范（6.3节）跑评测集验证后再上线。

**Q：不涉及微调，第七章怎么办？**

Skill 会自动识别，将第七章标注为「暂不适用」并输出后续涉及微调时的数据建设预规划，不影响其他章节生成。
